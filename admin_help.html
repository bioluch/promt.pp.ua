JS PROMPT — Administrator Guide

The Admin Panel gives administrators full control over users, prompts, AI provider configuration, and the database itself. This guide covers every capability available to an admin account.

User Management Prompt Moderation AI Provider Config Database Backup & Restore EN / UK / ES

Accessing the Panel

Open /admin.html directly, or click 🛡 Admin Panel in the user dropdown menu on the main app page. Access requires signing in with an account whose role is admin — regular user accounts are redirected with an "Admin access required" message.

Role check: the panel checks your role on every page load. If your admin rights are revoked while a session is open, you'll be blocked on the next refresh.

Dashboard

The landing section after signing in. Shows platform-wide counters and recent activity at a glance.

Stat cards

Total Users, Active Users, Total Prompts, Pending Jobs, and Completed Jobs — refreshed on every visit to the section.

Events by type

A table of recorded usage events grouped by type and count, useful for spotting unusual activity.

Users

Full list of registered accounts with per-user metrics and management actions.

Actions

+ Add User

Create a new account directly — email, password, optional display name, and role (User or Admin).

Active / Disabled toggle

Click the status button to instantly enable or disable sign-in for that account, without deleting any data.

Promote / Demote

Switch a user between user and admin roles with one click.

Delete

Permanently removes the account and all of their prompts, jobs, and data. Requires confirmation. Cannot be undone.

🔑 API Keys Management

Each user stores their own API keys in the database, tied to their account. Administrators can view, add, edit, and delete keys for any user via the 🔑 API Keys button in the Users table — without needing to know the full key value.

User Search

Type any combination of characters in the search field to instantly filter the users table. Matching rows are highlighted. If no results match, a "No users found" message appears.

provider_key
🔒 locked

Unique internal identifier. Lowercase letters, digits and underscores only (e.g. claude, gemini, my_llm). Set once at creation — cannot be changed, as it is the primary key referenced by Scheduled Jobs. Changing it would orphan all existing jobs targeting this provider.

label
required

Display name shown in dropdowns and the provider list (e.g. Claude, Gemini 2.5 Flash). Has no technical effect — purely cosmetic.

endpoint_url
required

Full API URL the Scheduler calls when making inference requests. For Gemini v1beta use {model} as a placeholder — the Scheduler substitutes the actual model name at runtime. Examples: https://api.anthropic.com/v1/messages, https://api.openai.com/v1/chat/completions.

model_name
required

Model identifier sent verbatim in the request body (e.g. claude-sonnet-4-6, gemini-2.5-flash, gpt-4o). Must exactly match the value the provider's API expects.

auth_header
optional

HTTP header name used to send the API key. Default: Authorization. Claude uses x-api-key instead. Leave as-is unless the provider requires a non-standard header.

auth_prefix
optional

Text prepended to the API key value. Default: Bearer  (with trailing space). Some providers need an empty prefix or a different word. The Scheduler concatenates: auth_prefix + api_key.

provider_options
optional · JSON

Provider-specific extra parameters sent in every API request body. Must be valid JSON. The Scheduler merges this object with the base request payload at runtime.

Common patterns:

is_active
☑ checkbox

When unchecked, the Scheduler skips this provider and all Scheduled Jobs targeting it will fail with a "provider not found" error. Use to temporarily disable a provider without deleting it.

is_builtin
☑ checkbox

Marks the provider as a core system provider. Built-in providers show a builtin badge in the list. Deleting a built-in triggers a stronger confirmation warning. Checking this box does not protect the provider from deletion — it only changes the UI warning level.

Export / Import

↑ Export

Downloads all providers as a JSON file (ai_providers_YYYY-MM-DD.json). Use for backup before changes, or to migrate providers to another instance.

↓ Import

Reads a JSON file exported from any instance. Uses ON CONFLICT … DO UPDATE — existing providers are updated, new ones are inserted. Does not delete providers absent from the file.

Built-in deletion: deleting a built-in provider (e.g. Gemini) shows an extra warning because all Scheduled Jobs targeting that provider_key will immediately start failing.

Danger Zone — Database Backup

Creates a full PostgreSQL backup (schema + data) and stores it as a downloadable .sql.gz file on the server.

1

Click "Create Backup"

Runs pg_dump on the server, strips owner/privilege/extension statements for portability, and compresses the result.

2

Find it in the list

Every backup appears with filename, size, and creation time, newest first.

3

Download anytime

Click Download to save the .sql.gz file to your computer for off-server safekeeping.

Tip: download a fresh backup before any risky operation — restoring or wiping the database.

Danger Zone — Restore Database

Restores the database from a backup, overwriting all current data. Two ways to do it:

Restore from server list

Click Restore next to any backup already stored on the server.

Upload & Restore

Choose a .sql.gz file from your computer and restore directly from it — the file is also saved to the server's backup list afterward.

Type-to-confirm: both paths require typing the word RESTORE in a confirmation dialog before proceeding — a safeguard against accidental clicks on this irreversible action.

The restore runs inside a single database transaction: if any statement fails, PostgreSQL automatically rolls back every change, so the database is never left half-restored.

Danger Zone — Wipe Database

Permanently deletes every user account except your own, along with all of their prompts, source texts, scheduled jobs, and API keys. Your own admin account and the AI Provider configuration are preserved.

Double confirmation: two separate confirmation dialogs must be accepted in sequence before the wipe executes. There is no undo — always create a fresh backup first.

Interface Language

The admin panel footer (left sidebar, below "Back to app") has an EN / UK / ES switcher. Your choice is remembered in this browser and applies to every section, dialog, and this Help window.

FAQ

Can I undo a database wipe or restore? ▼
No. Both actions are permanent. Always create and download a backup beforehand using "Create Backup" in the Danger Zone.
What happens if I delete a built-in AI provider? ▼
Any Scheduled Job pointing at that provider will start failing. The confirmation dialog warns about this before deletion.
Can I change a user's role without deleting their account? ▼
Yes — use the Promote / Demote button in the Users table. It switches between "user" and "admin" instantly.
Can I move a prompt to a different user? ▼
Yes — open the prompt with View, change the "User (email)" field, and click Save Changes. Or use Copy to duplicate it onto another account while keeping the original.

Доступ до панелі

Відкрийте /admin.html безпосередньо, або натисніть 🛡 Адмін-панель у меню користувача на головній сторінці застосунку. Доступ потребує входу з облікового запису, чия роль — admin; звичайні облікові записи отримують повідомлення "Для цього облікового запису потрібен доступ адміністратора".

Перевірка ролі: панель перевіряє вашу роль при кожному завантаженні сторінки. Якщо права адміністратора відкликано під час активної сесії, доступ буде заблоковано після наступного оновлення.

Експорт / Імпорт

↑ Експорт

Завантажує всіх провайдерів як JSON-файл (ai_providers_YYYY-MM-DD.json). Використовуйте для резервної копії або перенесення на інший сервер.

↓ Імпорт

Зчитує JSON-файл, експортований з будь-якого екземпляра. Використовує ON CONFLICT … DO UPDATE — існуючі провайдери оновлюються, нові додаються. Провайдери, відсутні у файлі, не видаляються.

Видалення вбудованого провайдера: видалення вбудованого провайдера (наприклад Gemini) показує додаткове попередження, оскільки всі заплановані задачі з цим provider_key негайно почнуть завершуватись помилкою.

Небезпечна зона — Резервна копія бази даних

Створює повну резервну копію PostgreSQL (схема + дані) і зберігає її як файл .sql.gz, доступний для завантаження з сервера.

1

Натисніть "Створити резервну копію"

Запускає pg_dump на сервері, видаляє команди власника/прав/розширень для переносимості, і стискає результат.

2

Знайдіть її у списку

Кожна резервна копія з'являється з назвою файлу, розміром і часом створення, найновіші — першими.

3

Завантажте будь-коли

Натисніть Завантажити, щоб зберегти файл .sql.gz на свій комп'ютер для зберігання поза сервером.

Порада: завантажте свіжу резервну копію перед будь-якою ризикованою операцією — відновленням чи очищенням бази даних.

Небезпечна зона — Відновлення бази даних

Відновлює базу даних з резервної копії, перезаписуючи всі поточні дані. Два способи зробити це:

Відновлення зі списку на сервері

Натисніть Відновити поруч із будь-якою резервною копією, що вже зберігається на сервері.

Завантажити та відновити

Оберіть файл .sql.gz зі свого комп'ютера і відновіть базу безпосередньо з нього — файл також буде збережено у списку резервних копій на сервері.

Підтвердження текстом: обидва шляхи вимагають ввести слово RESTORE у діалозі підтвердження перед продовженням — запобіжник проти випадкових кліків на цій незворотній дії.

Відновлення виконується всередині однієї транзакції бази даних: якщо будь-яка команда дає збій, PostgreSQL автоматично відкочує всі зміни, тож база даних ніколи не залишається наполовину відновленою.

Небезпечна зона — Очищення бази даних

Назавжди видаляє усі облікові записи користувачів, крім вашого власного, разом з усіма їхніми промтами, вихідними текстами, запланованими задачами та API-ключами. Ваш власний обліковий запис адміністратора та конфігурація AI-провайдерів зберігаються.

Подвійне підтвердження: потрібно послідовно прийняти два окремі діалоги підтвердження перед виконанням очищення. Відновлення неможливе — завжди створюйте свіжу резервну копію спочатку.

FAQ

Чи можна скасувати очищення або відновлення бази даних? ▼
Ні. Обидві дії незворотні. Завжди створюйте та завантажуйте резервну копію наперед, використовуючи "Створити резервну копію" в Небезпечній зоні.
Що станеться, якщо я видалю вбудованого AI-провайдера? ▼
Будь-яка запланована задача, що використовує цього провайдера, почне завершуватись помилкою. Діалог підтвердження попереджає про це перед видаленням.
Чи можу я змінити роль користувача без видалення його акаунту? ▼
Так — використайте кнопку Підвищити / Понизити в таблиці Користувачів. Вона миттєво перемикає між "user" та "admin".
Чи можу я перенести промт на іншого користувача? ▼
Так — відкрийте промт через Перегляд, змініть поле "Користувач (email)" і натисніть Зберегти зміни. Або скористайтесь Копіювати, щоб дублювати його на інший акаунт, зберігши оригінал.

provider_key
🔒 bloqueado

Identificador único interno. Solo letras minúsculas, dígitos y guiones bajos (p. ej. claude, gemini, my_llm). Se establece una vez al crear — no puede cambiarse, ya que es la clave primaria referenciada por las Tareas programadas. Cambiarlo dejaría huérfanas todas las tareas existentes.

label
obligatorio

Nombre visible en listas desplegables y la tabla de proveedores (p. ej. Claude, Gemini 2.5 Flash). No tiene efecto técnico — es puramente cosmético.

endpoint_url
obligatorio

URL completa de la API que llama el Programador al hacer solicitudes de inferencia. Para Gemini v1beta use {model} como marcador de posición — el Programador lo sustituye por el nombre real del modelo en tiempo de ejecución.

model_name
obligatorio

Identificador del modelo enviado literalmente en el cuerpo de la solicitud (p. ej. claude-sonnet-4-6, gemini-2.5-flash, gpt-4o). Debe coincidir exactamente con el valor que espera la API del proveedor.

auth_header
opcional

Nombre del encabezado HTTP usado para enviar la clave API. Predeterminado: Authorization. Claude usa x-api-key. Modifíquelo solo si el proveedor requiere un encabezado no estándar.

auth_prefix
opcional

Texto antepuesto al valor de la clave API. Predeterminado: Bearer  (con espacio). Algunos proveedores necesitan un prefijo vacío u otra palabra. El Programador concatena: auth_prefix + api_key.

provider_options
opcional · JSON

Parámetros adicionales específicos del proveedor enviados en cada solicitud. Debe ser JSON válido. El Programador fusiona este objeto con el cuerpo base de la solicitud en tiempo de ejecución.

Zona de peligro — Copia de seguridad de la base de datos

Crea una copia de seguridad completa de PostgreSQL (esquema + datos) y la guarda como un archivo .sql.gz descargable en el servidor.

1

Haga clic en "Crear copia de seguridad"

Ejecuta pg_dump en el servidor, elimina las instrucciones de propietario/privilegios/extensión para portabilidad, y comprime el resultado.

2

Encuéntrela en la lista

Cada copia de seguridad aparece con nombre de archivo, tamaño y hora de creación, las más recientes primero.

3

Descargue en cualquier momento

Haga clic en Descargar para guardar el archivo .sql.gz en su computadora para custodia fuera del servidor.

Consejo: descargue una copia de seguridad reciente antes de cualquier operación riesgosa — restaurar o borrar la base de datos.

Zona de peligro — Restaurar la base de datos

Restaura la base de datos desde una copia de seguridad, sobrescribiendo todos los datos actuales. Dos formas de hacerlo:

Restaurar desde la lista del servidor

Haga clic en Restaurar junto a cualquier copia de seguridad ya almacenada en el servidor.

Subir y restaurar

Elija un archivo .sql.gz de su computadora y restaure directamente desde él — el archivo también se guarda en la lista de copias de seguridad del servidor después.

Confirmación escrita: ambas rutas requieren escribir la palabra RESTORE en un diálogo de confirmación antes de continuar — una salvaguarda contra clics accidentales en esta acción irreversible.

La restauración se ejecuta dentro de una única transacción de base de datos: si alguna instrucción falla, PostgreSQL revierte automáticamente todos los cambios, por lo que la base de datos nunca queda parcialmente restaurada.

Zona de peligro — Borrar la base de datos

Elimina permanentemente todas las cuentas de usuario excepto la suya, junto con todos sus prompts, textos fuente, tareas programadas y claves API. Su propia cuenta de administrador y la configuración de proveedores de IA se conservan.

Doble confirmación: deben aceptarse dos diálogos de confirmación separados en secuencia antes de ejecutar el borrado. No hay forma de deshacer — siempre cree primero una copia de seguridad reciente.

FAQ

¿Puedo deshacer un borrado o restauración de la base de datos? ▼
No. Ambas acciones son permanentes. Siempre cree y descargue una copia de seguridad de antemano usando "Crear copia de seguridad" en la Zona de peligro.
¿Qué sucede si elimino un proveedor de IA incorporado? ▼
Cualquier Tarea programada que apunte a ese proveedor comenzará a fallar. El diálogo de confirmación advierte sobre esto antes de la eliminación.
¿Puedo cambiar el rol de un usuario sin eliminar su cuenta? ▼
Sí — use el botón Promover / Degradar en la tabla de Usuarios. Cambia instantáneamente entre "usuario" y "administrador".
¿Puedo mover un prompt a otro usuario? ▼
Sí — abra el prompt con Ver, cambie el campo "Usuario (correo)" y haga clic en Guardar cambios. O use Copiar para duplicarlo en otra cuenta conservando el original.
